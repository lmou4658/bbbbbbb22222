3. 优化 Anthropic / Bedrock prompt cache 断点策略

当前 applyBedrockAnthropicPromptCache() 不要再只从 messages 开头开始标记前 4 个 cache_control。

请改成适合长篇 SillyTavern RP 的缓存断点策略：

目标：
- 对 anthropic/ 开头的 OpenRouter Claude 模型启用 prompt cache；
- 包括 anthropic/claude-opus-4.6 和 anthropic/claude-opus-4.6:thinking；
- 如果模型名带 :thinking，应先 normalize 成不带 :thinking 的模型名，再判断是否启用缓存；
- 每次请求最多添加 4 个 cache_control，因为 Anthropic / Bedrock 上限是 4 个；
- 最后一条用户消息永远不要加 cache_control，因为它每轮都会变化；
- 短对话不要报错，也不要产生副作用。

长对话策略：
如果 messages.length > 20，请最多选择 4 个 cache_control 断点，分布在：

1. system 消息，如果存在；
2. 历史消息约 1/3 位置；
3. 历史消息约 2/3 位置；
4. 靠近末尾、但不是最后一条用户消息的稳定历史消息。

短对话策略：
如果 messages.length <= 20：
- 优先 system 消息；
- 然后从靠近末尾的稳定历史消息开始补足；
- 最多仍然 4 个；
- 不要给最后一条用户消息加 cache_control。

cache_control 添加方式：
- 如果 message.content 是 string，则转换成：
  [{ type: "text", text: content, cache_control: { type: "ephemeral" } }]
- 如果 message.content 是数组，则给最后一个 type === "text" 的 block 增加：
  cache_control: { type: "ephemeral" }
- 如果没有 text block、content 为空、或者是最后一条消息，则不要加 cache_control。

建议新增 helper function：

function pickCacheBreakpointIndexes(messages: OAIMessage[], maxBreakpoints: number): number[]

逻辑建议：
- finalIndex = messages.length - 1
- candidates = 所有 index < finalIndex 且 content 可缓存的消息
- systemIndex = candidates 里第一个 role === "system" 的消息
- historyCandidates = candidates 排除 system
- 如果 system 存在，先加入 systemIndex
- 如果 messages.length > 20：
    加入 historyCandidates[Math.floor(historyCandidates.length * 1 / 3)]
    加入 historyCandidates[Math.floor(historyCandidates.length * 2 / 3)]
    加入 historyCandidates[historyCandidates.length - 1]
    如不足 4，再补 historyCandidates[Math.floor(historyCandidates.length * 0.85)]
- 如果 messages.length <= 20：
    从 historyCandidates 靠近末尾开始补足剩余名额
- 去重，过滤无效 index
- 最终数量不能超过 4
